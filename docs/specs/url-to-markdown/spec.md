# URL을 Markdown으로 변환해 LLM으로 넘기기

웹 페이지 URL을 붙여넣으면 본문을 Markdown으로 추출해 보여 주고, 복사·다운로드하거나 ChatGPT·Claude로 바로 넘기는 한 화면짜리 서비스입니다.

## 사용자에게 보이는 결과

1. **입력**: URL 입력란에 주소를 붙여넣고 변환합니다. 지우기 버튼은 입력과 결과를 모두 초기 상태로 되돌립니다.
2. **변환**: 페이지 본문을 Markdown으로 추출합니다. 변환 중에는 로딩 상태가 보입니다.
3. **결과 확인**: 결과 위쪽에 페이지 제목과 저자를 보여 주고, 그 아래에 렌더링된 Markdown을 보여 줍니다. 저자 정보가 없는 페이지는 저자 줄을 생략합니다.
4. **내보내기**
   - 복사하기: Markdown 본문을 클립보드에 복사합니다.
   - .md 다운로드: Markdown 본문을 `.md` 파일로 내려받습니다.
   - ChatGPT로 열기 / Claude로 열기: 선택한 프롬프트(없으면 생략)를 본문 앞에 붙여 해당 서비스로 넘깁니다.
5. **프롬프트 선택**: 프리셋 "요약해줘", "한국어로 번역해줘", "쉽게 설명해줘"와 "직접 입력" 중 하나를 고르거나 아무것도 고르지 않을 수 있습니다. "직접 입력"을 고르면 텍스트 입력란이 나타납니다. 직접 입력한 문구는 1회용이며 저장하지 않습니다(새로고침하면 사라집니다).
6. **다크모드**: 토글로 라이트/다크를 전환합니다.

화면 구성과 상태(입력, 변환 중, 결과, 긴 글, 오류, 다크모드, 휴대폰 폭)의 기준은 승인된 [prototype.html](prototype.html)입니다. 입력란 안쪽 오른쪽에 지우기(원 안의 X, 평소 투명, 포커스·올림 시 윤곽)와 변환하기(원 안의 오른쪽 화살표) 버튼을 두는 배치도 여기서 정했습니다.

## 범위

- 포함: 위 흐름 전체, 오류·빈·로딩 상태.
- 제외: 로그인, 변환 기록 저장, 프롬프트 저장, 여러 URL 일괄 처리, ChatGPT·Claude 외 다른 LLM.

## 수용 기준

- 공개된 글 URL(예: Wikipedia 문서)을 입력하면 제목, 저자(있을 때), Markdown 본문이 표시됩니다.
- 지우기를 누르면 입력란, 결과, 오류 메시지가 모두 사라집니다.
- 복사하기를 누르면 클립보드에 Markdown 본문이 들어가고, 복사됐다는 피드백이 보입니다.
- .md 다운로드는 Markdown 본문을 담은 파일을 내려받습니다. 파일명은 페이지 제목을 바탕으로 합니다.
- LLM으로 열기는 프롬프트(선택한 경우)와 본문을 합친 글자 수에 따라 다르게 동작합니다.
  - 합친 글자 수가 6,000자 이하이면 ChatGPT 또는 Claude의 새 채팅이 새 탭에서 열리고, 프롬프트와 본문이 질문란에 채워져 있습니다.
  - 6,000자를 넘으면 합친 텍스트를 클립보드에 복사하고, 해당 서비스의 빈 새 채팅을 새 탭으로 엽니다. 화면에는 "내용이 길어 클립보드에 복사했습니다. 새 채팅에 붙여넣기(Ctrl+V)하세요"라는 안내가 보입니다.
  - 본문을 말없이 자르지 않습니다.
- 프롬프트를 고르지 않으면 본문만 넘어갑니다. 프리셋을 고르면 해당 문구가 본문 앞에 붙고, "직접 입력"을 고르고 입력란이 비어 있으면 프롬프트 없이 본문만 넘어갑니다.
- 잘못된 URL 형식이거나, 페이지를 가져오지 못했거나, 본문을 추출하지 못한 경우 원인을 알려 주는 오류 메시지가 보이고, 입력한 URL은 그대로 남아 다시 시도할 수 있습니다.
- 다크모드 토글이 모든 화면 요소에 적용됩니다.
- 좁은 화면(휴대폰 너비)에서도 입력, 결과, 내보내기 동작이 모두 사용 가능합니다.

## 확정된 제약과 근거

- **defuddle 라이브러리를 사용합니다.** 사용자 요구입니다(문서: https://defuddle.md/docs).
- **변환은 서버에서 수행합니다.** 브라우저는 다른 사이트의 HTML을 CORS 때문에 직접 가져올 수 없습니다. 이 프로젝트 환경과 같은 조건의 scratch 디렉터리에서 `defuddle/node`와 `linkedom`으로 Wikipedia 문서를 변환해, `title`, `author`, Markdown `content`가 나오는 것을 확인했습니다(defuddle 0.19.5). 확인하지 못한 것은 이 프로젝트의 Next.js 서버 런타임 안에서의 동작이므로 구현 때 실제 화면 흐름으로 검증해야 합니다.
- **LLM 넘기기는 6,000자 기준 하이브리드입니다(사용자 확정).** 긴 본문은 URL 길이 한도 때문에 `?q=`로 넘기면 잘리거나 열리지 않습니다. 자르면 사용자가 일부만 분석된 줄 모르고 쓰게 되어서, 길 때는 클립보드와 안내로 대신합니다.
- UI는 [ui-composition](../../decisions/ui-composition.md) 계약을 따릅니다. 공식 shadcn component와 semantic token을 쓰고, 입력·결과·내보내기의 위계, loading·error·empty·success 상태, 좁은 화면에서의 쌓기를 포함해 이 계약이 정한 기준을 적용합니다.

## 가정(바꾸고 싶으면 알려 주세요)

- ChatGPT는 `https://chatgpt.com/?q=`, Claude는 `https://claude.ai/new?q=` 형태로 질문란을 채울 수 있다고 가정합니다. 이 쿼리 파라미터는 이번 shaping에서 직접 확인하지 않았습니다. 구현 때 실제로 채워지는지 확인하고, 동작하지 않으면 모든 경우를 클립보드 방식으로 처리합니다.
- 6,000자는 프롬프트와 본문을 합친 글자 수 기준입니다. 서비스별 실제 한도에 맞춘 값이 아니라 여유를 둔 보수적인 값입니다.
- 프리셋 문구는 버튼 이름과 같은 "요약해줘", "한국어로 번역해줘", "쉽게 설명해줘"를 그대로 사용합니다.
- 프리셋과 "직접 입력"은 하나만 선택할 수 있고, 선택하지 않을 수도 있습니다. 기본값은 선택 없음입니다.
- Markdown 렌더링은 본문의 제목, 목록, 링크, 코드, 표를 읽기 좋게 보여 주는 수준이며, 원본 페이지의 스타일은 재현하지 않습니다.
- 앱 전체 제품 정의(`PRODUCT.md`)는 아직 없어서 적용할 앱 수준 제약이 없습니다.

## 건드리지 않는 영역

- `docs/decisions/ui-composition.md`와 설치된 skill은 수정하지 않습니다.
- 사용자 데이터를 서버나 외부에 저장하지 않습니다. 입력한 URL과 직접 입력 프롬프트는 저장 대상이 아닙니다.

## 보류한 항목

- 자바스크립트로 본문을 그리는 페이지(SPA)와 로그인이 필요한 페이지: 이번 범위에서는 지원을 약속하지 않습니다. 이런 페이지는 위 오류 메시지 경로로 처리됩니다. 지원이 필요해지면 별도 결정이 필요합니다.
- 서버가 임의의 URL을 가져오는 데 따른 보안 하드닝(내부 주소 차단 등): 이 프로젝트의 검증 예산상 범위 밖입니다.

## 남은 위험

- LLM 서비스의 `?q=` 파라미터가 바뀌거나 동작하지 않으면 "바로 넘기기"가 클립보드 방식으로 후퇴합니다.
- 일부 사이트는 서버의 요청을 차단하거나 본문 추출 결과가 빈약할 수 있습니다.
- defuddle의 서버 측 동작은 이 프로젝트 안에서 아직 확인하지 않았습니다.
